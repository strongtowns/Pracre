Pracre 1.1 reads parcel data in any coordinate system, links more kinds of assessment files correctly and fixes a long list of import and display problems found by testing against open data from Vancouver, Edmonton, Calgary, New York City, Philadelphia, Wake County (North Carolina), Massachusetts and France.

**Downloads**

- **Windows 10 and 11** `Pracre-Windows-x64-Setup.exe` (installer) or `Pracre-Windows-x64-Portable.zip`
- **macOS 12 or later, Intel and Apple silicon** `Pracre-macOS-Universal.dmg`. On first launch, right-click Pracre and choose Open.
- **Ubuntu 22.04 or later, Debian 12** `Pracre-Linux-x64.deb` (`sudo apt install ./Pracre-Linux-x64.deb`)
- **Other Linux** `Pracre-Linux-x64.tar.gz` (needs WebKitGTK 4.1; run `./install.sh`)

**Every coordinate system**

- All 7,800 EPSG and ESRI projected systems and 1,400 geographic ones are built in, so a bare code such as EPSG:2264 or an ArcGIS wkid works offline. State Plane files from ArcGIS now land in the right place without pasting a .prj.
- Adds the projection methods real parcel data uses, including Krovak, Swiss and Dutch grids, oblique and polar stereographic, Cassini, Polyconic and Lambert azimuthal, and reads axes stored southing or westing first. Every method matches PROJ to within a centimetre.
- Older datums such as NAD27, OSGB36, ED50, MGI and Tokyo are shifted to WGS 84 with the regional transformation for where the data sits, usually within a few metres.
- WKT2 text pasted from epsg.io works, as do .prj files that name only their datum.
- Unlabelled coordinates are tried in every system near the map view. In the import window, "Guess for This Area" ranks the systems again for wherever the small map is moved, which settles State Plane files that fit many states.

**More location formats**

- MGRS / USNG grid references, UTM text such as "10U 525199 5432031", Plus codes and geohashes in a column.
- Hex WKB geometry, as in Philadelphia's assessment CSV and other PostGIS or Carto exports.
- Opendatasoft JSON exports, UTF-16 text from Excel, decimal commas in semicolon-separated files, and CSV files with title rows above the header.

**Better values and links**

- Multi-year exports, such as Vancouver's tax report, use only the latest roll year instead of adding the years together.
- Values tables that repeat a lot's ID for every strata unit link by that ID, so condo units reach their lot.
- Columns such as current_land_value, county values and taxable land plus buildings are recognised; ID, legal description and building count columns are no longer read as values or locations.
- Strata, condo and HOA units drawn in holes cut out of their common property fold into that lot with their land, so a townhouse complex split across two civic addresses reads as one lot.
- Dropping all of a shapefile's parts at once imports it once, without extra tables.
- Empty files and ArcGIS error replies give a clear message.

**Fixes in the app**

- File > Sample Data opens the whole Township of Langley or every parcel in Port Huron, Michigan with 2024 taxable values. Opening a sample replaces the data that was loaded.
- Windows installs into Program Files\STCD\Pracre, and the About dialog and Help menu link to strongtowns.dev.
- Opening a project restores its display settings and camera.
- The Tax Rates table keeps rows and units edited while a save is in progress, and deleted rows disappear at once. Rates typed with a decimal comma read correctly.
- The insight card, image and web map titles follow the measure on the map (value or tax, per acre or per hectare).
- The map moves to the data when a dataset's location changes, and switching to 3D no longer cuts short a zoom to the data.
- The import window's small map stays in place while you edit, with zoom buttons, and marking a column as a tax rate no longer breaks the window.
- The checklist explains when a values file covers more ground than the parcels, and points to the link settings when no values reach the map.
- CSV exports can no longer carry spreadsheet formulas from imported text.
